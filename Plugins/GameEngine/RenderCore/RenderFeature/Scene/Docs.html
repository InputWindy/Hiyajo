Scene.h —— 全局渲染资源特性（共享场景目标）

`Scene::FScene` 是**全局渲染资源特性**（对齐 UE 的做法）：它挂渲染录制阶段的 stage，**跨帧拥有共享的场景目标**（`SceneColor` / `SceneDepth`）。别的特性经 `Scene::GetScene()` 读它们 —— **不在 `FRender` 里开命名槽位**：要共享的东西提供者是明确的一个，用访问器比用「按名字查表」更直接（名字查表还会把共享变成隐式依赖）。目标在交换链尺寸变化时重建。

它同时是**绘制协议的生产者**（硬编码的全屏三角形），也是「布局切换」的负责人（见下面的卡片）。

为什么 SceneColor 要显式切布局

这是这个头里最值得记住的一条约束：**同一个目标，两种用途，两种布局，而且 RHI 不会自动转换**。

环节说明
渲染目标侧场景自己拥有：`Render()` 写入之前确保 `COLOR_ATTACHMENT_OPTIMAL`
采样源侧编辑器视口把 SceneColor 当镜像读，需要 `SHADER_READ_ONLY_OPTIMAL`
切换责任渲染目标侧由场景自己负责；采样侧由采样方调 `TransitionSceneColorForSampling` / `TransitionSceneColorForRendering` 来回切
漏切的后果RHI 的描述符写入写死 `SHADER_READ_ONLY`，而图像还在 `COLOR_ATTACHMENT_OPTIMAL`（或 `UNDEFINED`）⇒ 校验层报布局不匹配

本特性与别的特性的依赖边（读各特性的构造函数）

消费者声明含义
FDrawTriangleFeature`MyStage<IRender>().IsWaiting<Scene::FScene>().ForStage<IEndRender>()`在场景那批提交之后画三角形（叠在清理之上）
FUIFeature`MyStage<IRenderUI>().IsWaiting<Scene::FScene>().ForStage<IEndRender>()`UI 合成在场景之后（合成在场景之上）
FUIFeature`MyStage<IInitViews>().IsWaiting<Scene::FScene>().ForStage<IBeginRender>()`**数据流边**：视口镜像的解析必须看到**当前**目标 —— 尺寸变化时 `EnsureTargets` 会销毁并重建 SceneColor，没有这条边，并行 worker 上的 `IInitViews` 可能解析到重建前的陈旧镜像，`RenderUI` 于是把**新** SceneColor 切到 SR 却画**旧**的（还在 `COLOR_ATTACHMENT_OPTIMAL`）⇒ `vkCmdDraw` 布局不匹配校验错

类 FScene : FFrameExtension, IPipeline<IBeginRender, IRender, IEndRender, IPreUnInstall>

共享场景目标 + 场景绘制阶段的所有者。它挂四个 stage：`IBeginRender`（建 / 重建目标）、`IRender`（录场景清理 / 绘制）、`IEndRender`（收尾 —— **别人等的是这个**）、`IPreUnInstall`（卸载前释放共享目标）。

接口

访问域接口签名说明
publicFScene()构造：① 把自己登记为全局单例（`GScene = this`，给 `GetScene()`）；② 预置绘制协议的测试数据 —— 硬编码全屏三角形（`VertexCount = 3`，**没有顶点缓冲**，顶点着色器用 `gl_VertexIndex` 现场生成三个位置，所以 `AddPass` 录成 `Draw(3)`）。**为什么 `IBeginRender` 取列表不会与回收抢：**宿主 `FRender::BeginFrame`（引擎 stage）已经等过上一帧栅栏、回收过上一帧列表并开好了帧缓冲
public~FScene() override析构：清空全局单例（`GScene = nullptr`）—— 之后 `GetScene()` 返回空
public[[nodiscard]] FRDGTextureRef GetSceneColor() const共享场景颜色目标（**双重身份**：既是渲染目标，也是被采样源 —— 见下面的布局卡片）
public[[nodiscard]] FRDGTextureRef GetSceneDepth() const共享场景深度目标
public[[nodiscard]] const FDrawList& GetTriangleDrawList() const绘制协议的**测试生产者**：硬编码的全屏三角形列表。`AddPass` 原样消费它，**永远不知道它来自这里** —— 以后换成真正的场景渲染器时消费方一行不改
publicvoid BeginRender(FRender& R) override帧首：`EnsureTargets(R)` 按画布尺寸建 / 重建目标。清理**不在这里录** —— 它在 `Render` 里经 `AddPass` 录进本帧的有序表，本特性不持有命令列表
publicvoid Render(FRender& R) override录场景 pass（清理 + 绘制）——只录，提交在帧尾
publicvoid EndRender(FRender& R) override收尾 stage —— **它是别的特性的排序锚**：「我的绘制要在场景之后」等价于「等 FScene 的 IEndRender」，于是两条列表的登记顺序被这条边钉死
publicvoid Present(FRender& R) override**帧尾 / 上屏**（本 change 新增的实现）：① `SubmitRecordedPasses` 按序提交离帧表 + 本帧所有 pass；② 把最终目标 blit 到交换链。它是**整帧唯一的提交点**，所以每个会录 pass 的 stage 都必须声明 `IsBlocking<Scene::FScene>().OnStage<IPresent>()`
publicvoid PreUnInstall(FRender& R) override**在本模块卸载之前**释放共享目标。FScene 是 FRender 的子插件（在 FRender 关闭期间被卸载），而 `SceneColor` / `SceneDepth` 是登记在**资源系统**里的 —— 资源系统比它活得久。留着不管就会出「资源系统销毁一个所属模块已经没了的对象」这类已验证过的崩溃（子插件比 `FResourceSystem::Shutdown` 先卸载）。实现是 `RS->DestroyResource("SceneColor"/"SceneDepth")` + 清引用 / 布局 / 尺寸缓存
publicvoid TransitionSceneColorForSampling(FRender& R)把 SceneColor 切到 `ShaderResource`（供下游按纹理采样）。**何时调用：**采样方（典型是编辑器合成 pass）在它采样之前调，否则 RHI 的描述符写入写死 `SHADER_READ_ONLY`、而图像还在 `COLOR_ATTACHMENT_OPTIMAL`（或从未转换过的新目标还在 `UNDEFINED`），校验层直接报错
publicvoid TransitionSceneColorForRendering(FRender& R)把 SceneColor 切回渲染目标布局（采样方用完必须切回；场景自己在 `Render` 里、写入之前也会确保是渲染目标布局）
privateUndefined从未转换过（新目标 / 第一次 Render 之前）
privateRenderTarget上次离开时是 `COLOR_ATTACHMENT_OPTIMAL`
privateShaderResource上次离开时是 `SHADER_READ_ONLY_OPTIMAL`
privatevoid EnsureTargets(FRender& R)按 `R.GetCanvasWidth()/GetCanvasHeight()` 建 / 重建 SceneColor + SceneDepth；尺寸变化（或首次）时重建并置 `bTargetsNeedTransition = true`（新目标需要一次 `Common → RenderTarget`）
