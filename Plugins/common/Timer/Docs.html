Timer.h —— 分层作用域计时（服务层）

基于**栈**的作用域性能剖析：`FScopedTimer` 在构造时 `BeginScope`、析构时 `EndScope`，`FTimer` 把每次弹出累加进一棵按名字分层的计时树，`DumpToString()` 输出文本报告。

**为什么用 RAII 作用域而不是手工开始 / 结束**：热路径上最怕的是「提前 return / 抛异常导致 EndScope 被跳过」，那会让计时栈永久错位。把一对调用绑在对象生命周期上，正确性由语言保证，调用点也短到可以随手插进任何函数。

**为什么是树而不是打平的表**：`Render → Scene → Cull` 这种嵌套关系本身就有信息量（父层耗时包含子层），打平后会丢掉「谁被谁包含」，而树可以既打印自身又打印包含关系。

**为什么用单调钟**：`std::chrono::steady_clock` 不受系统时间调整影响 —— 用 `system_clock` 的话，一次 NTP 校时就能造出负耗时或巨大尖峰。

计时节点字段（FTimer::FNode）

节点是**聚合**类型（无自定义构造），全部字段公开给本帧自己使用；这里列出它们是为了说明每棵计时树到底记住了什么。

字段含义
std::string Name节点名（作用域名；同名作用域复用同一节点，于是「调用一次」变成「累加一次」）
double TotalSeconds累计自身耗时（**不含子节点**的净值，便于看清本层开销）
double MaxSeconds单次最大耗时 —— 平均值会掩盖偶发尖峰，它不会
std::uint32_t Count调用次数（与 Total 一起才能得到平均值）
std::chrono::steady_clock::time_point Start本次进入的时间点（弹出时用它算差值）
FNode* Parent父节点 —— **裸指针**：树由 `Root` 唯一拥有，`Parent` 只是回溯链，不参与所有权
std::map<std::string, FNode> Children子节点表（按值持有 ⇒ 整棵树随 `Root` 一次析构；`map` 保证遍历顺序稳定）

类 FTimer : FFrameExtension, IPipeline<IPreInit, IInit, IPostInit, IPreShutdown, IShutdown, IPostShutdown>

计时器本体 —— **一个帧**（挂 6 个 stage）：`Initialize` 发布全局访问点，`Shutdown` 撤销。

**为什么是帧而不是纯静态**：计时树对当前作用域栈（`Current`）有状态，而这份状态必须只有一份、且有明确的生命周期；交给有依赖排序的帧持有，「谁在谁之前计时」才有确定性。

**为什么要 `Reset`**：计时数据是「一段区间」的采样，看一帧 / 一段加载的耗时必须能清零 —— 否则累计值随时间单调增长，读不出局部热点。

**公平契约**：`BeginScope` 与 `EndScope` 必须配对（用 `FScopedTimer` 就没这个问题），不配对会让 `Current` 指针错位，之后的计时全部挂到错的父节点下。

类 FScopedTimer

RAII 作用域计时器：构造即 `BeginScope(Name)`，析构即 `EndScope()`：

`void Render() { Timer::FScopedTimer Scope("Render"); /* 工作 */ }` —— 进入即开始，离开自动结束。

**为什么禁止拷贝与赋值**：两个对象对应一次 `BeginScope` / `EndScope`，拷贝会让「构造 / 析构」的次数与实际的进入 / 离开次数脱钩（多出或少掉一次弹出），计时栈随即错位 —— 因此直接在类型层面禁掉，而不是靠注释提醒。

**为什么它自己不含数据**：所有状态都在 `FTimer` 那一棵树里，这个对象只是「进入 / 离开」这对动作的载体 ⇒ 它的大小可以忽略，放进热路径也不必担心额外开销。

头文件功能
Core/Export.h`MAHO_EXPORT` / `MAHO_IMPORT`（引擎核心提供）

宏 MAHO_TIMER_API : MAHO_EXPORT / MAHO_IMPORT（随构建开关切换）

编译 `Timer.dll` 时构建系统定义 `MAHO_TIMER_MODULE_EXPORTS` ⇒ `MAHO_EXPORT`；消费方为 `MAHO_IMPORT`。

**为什么必须有**：`FTimer* GetTimer()` 跨 DLL 返回类型，`FTimer` 的虚表与删除析构符必须只在本模块生成；`dllimport` 把「消费方各生成一份」变成编译错误，避免卸载后 `delete` 静默崩。
