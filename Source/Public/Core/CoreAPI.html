Core — API 文档

Core 模块 = 引擎的编译期 + 运行时基础设施。零 app 假设、零三方依赖：类型无关的列表/拓扑/查询/队列/单例标识基类，加上线程池与模块加载原语。本文档按头文件分节，如实反映当前 Source/Public/Core/ 的公开接口。

TypeList.h

TTypeList<TTypes...>struct

编译期有序类型列表（"类型数组"）。顺序即语义：TTypeList<A,B> ≠ TTypeList<B,A>。遍历顺序（串/并行）由调用方决定，不在本类型编码。

成员变量

字段类型说明
Countconstexpr size_t类型个数

TCons / TAppend / TContains / TCatch / TUnionList_tstruct / alias

列表代数：前插、后插、成员判断、多表拼接、保序去重并集。全部编译期求值，结果经 ::Type / _t / _v 取用。

接口

签名说明
struct TCons<T, TList>::Type把 T 前插到 TList 头部
struct TAppend<TList, TValue>::Type / TAppend_t把 TValue 追加到 TList 尾部
struct TContains<TList, T>::value / TContains_vT 是否为 TList 的成员
struct TCatch<TLists...>::Type按序拼接多个 TTypeList（TCatch<TTypeList<A>, TTypeList<B,C>>::Type → TTypeList<A,B,C>）
using TUnionList_t<A, B>两表并集：保序 + 去重（折叠追加，已存在则跳过）

Queue.h

ICommandstruct（接口）

命令队列的运行时基类。类型擦除：FQueue 经 unique_ptr<ICommand> 持有，队列因此类型无关。GetCatalogId() 是路由键。命令是纯数据载体——执行完全是消费方的事（队列从不运行任何东西）。

接口

签名说明
virtual ~ICommand() = default虚析构
virtual uint64_t GetCatalogId() const = 0所属 catalog lane（uint64 键），路由到自己的 FIFO 队列

FQueueclass

线程安全、按 CATALOG 分区的待处理命令集合。非模板：命令以 unique_ptr<ICommand> 持有，每条命令自带 catalog id，Enqueue 路由进对应 lane，Dequeue 排空单个 lane（FIFO）。任何线程可 Enqueue，消费方在自己安全点 Dequeue 并自行执行（如 switch on GetCatalogId）。

接口

签名说明
void Enqueue(unique_ptr<ICommand>)按 GetCatalogId 入 lane（接管所有权；空指针忽略）
unique_ptr<ICommand> Dequeue(uint64_t)弹出该 lane 最旧命令（FIFO）；lane 空返回 nullptr，所有权转移给调用方
bool IsEmpty() const所有 lane 均无待处理命令
size_t Size() const全部 lane 待处理命令总数

Topology.h

FDefaultSlotstruct

默认依赖槽——lambda 驱动（无 stage）时的类型键。只靠排序不靠阶段的类用 FDepends（TTypeList<FDefaultSlot, TTypeList<...>>）键在此槽。

节点依赖声明：FDepends约定

节点在其内部用 using FDepends = TTypeList<Key, TTypeList<Deps...>>; 声明某 Key 下的依赖（也可经 MAHO_EXTEND_DEPS 宏展开，见 Extension.h）。拓扑算法只读这个类型，不认识任何阶段语义——Key 是宿主域的可比较常量（枚举值/整数），依赖强度与正逆序都是宿主策略。

Topo 编译期算法namespace

按 Key 的依赖分层（并行组）+ 编译期环检测。只吃每个节点的完整 FDepends 声明（不裁剪到调度集合，依赖可点名集合外的类）。

接口

签名说明
struct TNodeDepList<TNode, Key>::Type节点在 Key 下的依赖列表；无 FDepends（或无该 Key 槽）→ 空表
constexpr bool THasCycle_v<TNodes, Key>DFS 路径着色环检测（回边短路）
constexpr bool TIsAcyclic_v<TNodes, Key>无环判定 = !THasCycle_v，用于 static_assert
struct TNodeLevel<TNodes, Key, TNode>::Value节点层级 = 1 + max(依赖层级)；根为 0
struct TLevel<TNodes, Key, K>::Type恰好位于第 K 层的节点（层内无序，可并行）
struct TLevelsUpTo<TNodes, Key, K>::Type第 0..K 层，外层列表逐层
using TLevels_t<TNodes, Key>完整分层：外层 = 层序列（第 0 层先跑），内层 = 同层类型（互不依赖，可并行）。假定无环（先用 TIsAcyclic_v 验证）

MAHO_CLOSURE / MAHO_SORT_LEVELmacro

读取 code-gen 闭包：codegen 扫描每个类的 MAHO_EXTEND_DEPS，建全局图、算每个 (Class, Key) 的传递闭包、跑无环校验，把结果写进项目 .gen.h 的 MAHO_CLOSURE_0_<Class>_<Key> 宏。C++ 侧直接用即可。

接口

签名说明
MAHO_CLOSURE(Class, Key)Class 在 Key 下的完整依赖闭包（TTypeList<...>；codegen 保证无环且包含所有中间链）
MAHO_SORT_LEVEL(Class, Key)Class 在 Key 下的分层带 == Topo::TLevels_t<MAHO_CLOSURE(Class, Key), Key>

Query.h

TQuery<FList>class

类型无关的编译期 LINQ：输入 TTypeList，输出筛选后的 TTypeList。Select / With / Not 是编译期类型集合运算，可链式调用且纯净（不碰运行时状态、不引用 FLayer/scheduler）。每次调用返回新的 TQuery，其 FList 是截至当前的存活集合；FResult 就是这张运行表。驱动存活类型（实例经 layer、单例经 Get）是调用方的事。

接口

签名说明
using FResult = FList截至当前的存活类型表
constexpr auto Select<TInterfaces...>()保留派生自 任意 给定接口的类型（OR）——从 FList 起筛
constexpr auto With<TInterfaces...>()保留派生自 全部 给定接口的类型（AND）——在 FList 上细化
constexpr auto Not<TInterfaces...>()丢弃派生自 任意 给定接口的类型（NOR）——从 FList 中减去

Singleton.h

TSingleton<T>class（CRTP 标识基类）

仅身份/标志基类：没有 Get()、没有内联 Meyers、没有强制生命周期。每个派生单例自己声明 static T& Get(); 并在自己的 .cpp（编进其 DLL）里定义——实例只存在于一个 DLL 的一个编译单元 → 跨 DLL 进程唯一（此处若用内联 static local 会在每个 include 站点 DLL 各复制一份）。is_base_of_v<TSingleton<T>, T> 仍可识别单例（查询遍历不变）。需要生命周期（IInit/IShutdown）时经 IPlugin 组合，而非无条件继承。拷贝构造/赋值被删除。

约束

签名说明
TSingleton() protected受保护默认构造（仅派生可实例化）
static T& Get() （派生类声明，自己 cpp 定义）进程唯一实例入口——由派生类提供，不在本基类

Extension.h

FNoParentstruct

空依赖锚点——不声明 FDependsPack 语义，作为根 layer 的 Parent（无父边），或当依赖纯由 extras 拼出时使用：MAHO_EXTEND_DEPS((IRender, FNoParent)) → 根，无依赖。

MAHO_EXTEND_DEPSmacro（codegen 扫描锚点）

声明类在某个 Key 下的依赖槽（单 Key 形式）。编译器把该行展开成拓扑层读取的 FDepends 类型；依赖列表本身由 codegen 提供——Tools/scan_deps.py 扫描此标记，向同名 .gen.h 写入 #define MAHO_DEPS_<Class>_<Key> <deps...>。身份/能力用继承声明（IPlugin / FLayer 等），此宏只声明"依赖谁、在哪个槽/阶段"。

展开

签名说明
MAHO_EXTEND_DEPS(Class, Key, ...)展开为 using FDepends = TTypeList<Key, TTypeList<MAHO_DEPS_##Class##_##Key>>（gen.h 宏填完后 == TTypeList<Key, TTypeList<deps...>>）

Assembly.h

FModuleDeleterstruct

OS 模块句柄的自定义删除器——DLL 用 FreeLibrary / dlclose 释放而非 delete。FAssembly 独占该句柄，析构时释放。

接口

签名说明
void operator()(void* Handle) const noexcept释放句柄（nullptr 安全；Win: FreeLibrary / 其他: dlclose）

FAssemblyclass

动态加载的代码单元——OS 模块句柄 + 符号查找。纯加载原语：不认识插件/manifest/工厂，如何解释已加载模块（探测哪些符号、含义如何）全由消费方决定（插件管理器/薄启动器/项目自定义加载器）。所有权：句柄唯一所有者（unique_ptr → 只移不拷）；宿主必须在所有由它构造的实例存活期间保持 FAssembly 加载——先卸载再使用虚表/析构是 use-after-free。

接口

签名说明
FAssembly() = default空构造（未加载）
explicit FAssembly(string_view Path)构造即 Load
bool Load(string_view Path)从路径加载（Win: LoadLibraryA / 其他: dlopen RTLD_NOW）；失败返回 false（先 Unload 旧句柄）
void Unload()释放句柄（FreeLibrary / dlclose）；可重复调用
bool IsLoaded() const当前是否持有有效句柄
void* GetProcAddress(const char*) const原始符号查找；缺失或未加载 → nullptr
template<typename TFunction> TFunction GetProcAs(const char*) const把原始符号 reinterpret_cast 成类型化函数指针

ForEach<TList>function（模板）

展开 TTypeList，按类型调度访问，把每个类型以 TTag<T> 喂给 Visitor。Scheduler 需满足 FForEachScheduler，由它决定串/并行。扩展交互协议只有 visitor lambda：调度器只遍历列表/实例，把每个目标交给宿主传入的 visitor。

接口

签名说明

Parallel::FParallelSchedulerclass（并行调度器）

并行遍历基类（内置线程池）。继承 IScheduler，构造时自建 FThreadPool。两个 ForEach 重载：变参可调用包 / 运行时容器 + MakeTask；都在线程池并发执行、barrier 收尾。不含类型/layer/层级语义——依赖分层与实例分发是 layer 的事（FLayer 在 Query().ForEach 内持有 FLevels + DispatchInstance）。

接口

签名说明
template<typename... FCallables> void ForEach(FCallables&&...) const并行执行整个可调用包，全部完成才返回（barrier）。Sched.ForEach([]{A();}, []{B();}, []{C();}) → A/B/C 并行
template<typename TContainer, typename TTaskFn> void ForEach(const TContainer&, TTaskFn&&) const运行时容器：MakeTask 把每个元素映射成 std::function<void()> 工作项，并发执行、barrier 收尾。约束 begin/end/size 以与变参重载区分

ThreadPool.h

FThreadPoolclass

固定规模线程池（常驻 worker + 任务队列 + barrier）。Submit：入队一个 fire-and-forget 任务，立即返回；Run：并发执行所有可调用并阻塞到全部完成。构造时零 worker，经 EnsureThreads 惰性增长（并行调度器按扩展数扩容），NumThreads 是硬上限。任务必须线程安全——在不同 worker 上并发运行。只移不拷。

接口

签名说明
explicit FThreadPool(uint32_t NumThreads = 0)NumThreads=0 → std::thread::hardware_concurrency()（下限 1）；构造不建 worker，懒启动
void Submit(std::function<void()>)入队一个任务，立即返回
void EnsureThreads(uint32_t Required)懒增长到至少 Required 个 worker（永不缩减；不超过硬件上限）
struct FBarrier一批任务的共享 barrier 状态（Mutex + Cv + 原子 Remaining），堆分配共享，不绑调用方栈帧
template<typename... FCallables> void Run(FCallables&&...)在池上并发运行每个可调用，阻塞到全部完成（barrier）；0 个直接返回，1 个串行直跑
void RunTasks(std::vector<std::function<void()>>)并发运行运行时长度任务列表，阻塞到完成（同 barrier 语义）
uint32_t GetNumThreads() const当前线程数上限

ThreadedServer.h

FThreadedServerclass

专用常驻 worker：一个持久线程 + FIFO 串行任务队列。给需要私有常开线程 + 串行命令队列的长期角色用（渲染线程、IO 加载线程……）——不是瞬时并行任务（那种用 FThreadPool）。子类可覆写 OnInitialize / OnShutdown / GetThreadName 做角色化配置；Flush() 是 FIFO barrier。拷贝删除。

接口

签名说明
virtual ~FThreadedServer()析构时自动 Shutdown
bool Initialize()启动专用 worker；幂等；OnInitialize 失败返回 false
void Shutdown()停止 + join worker；幂等
bool IsRunning() constworker 是否在运行（原子读）
void Submit(std::function<void()>)入队一个任务（非阻塞、FIFO、串行执行）
void Flush()barrier：阻塞到本调用前提交的所有任务执行完
virtual bool OnInitialize() protected线程启动前回调；返回 false 中止启动（如资源系统在此解析根）
virtual void OnShutdown() protected线程 join 后回调
virtual const char* GetThreadName() const protected默认 "ThreadedServer"
