类 FAssembly

One loaded module: the OS handle, the symbol lookup on it, and the shared plugin manifest. The manifest is the `PluginManager.json` the path layer resolves: it is read ONCE per process by `LoadManifest()`, and it is what `GetChildren` answers from -- the plugin tree the engine installs frames along. A module is loaded by its own object and unloaded when that object goes away (`~FAssembly`), so an assembly must outlive every symbol taken out of it.

Public/Core/Delegate.h

Delegate.h

Multicast events: `TMulticastEvent<void(Args...)>` -- bind / broadcast / unbind, thread-safe, usable across a DLL boundary. A subscriber gets an opaque `FSubscriptionID` back and unbinds with it, so a listener that dies before its publisher can always detach (this is what makes "a service broadcasts to plugins" safe when a plugin is unloaded). `Broadcast` copies the handler list under the lock and then calls WITHOUT it: a handler may bind/unbind (or broadcast) re-entrantly, and holding the lock across the calls would deadlock on the first such handler. The event itself never crosses a DLL boundary as an interface: a publisher owns it and hands out subscription ids.

Public/Core/Export.h

Export.h

模块导出标签：`MAHO_EXPORT` / `MAHO_IMPORT` / `MAHO_API` 的三种形态。 各插件自己的标签（`MAHO_<NAME>_API`，由 codegen 生成）都以这里为基础：编译该模块的 DLL 时它是 `MAHO_EXPORT`，消费方是 `MAHO_IMPORT`。**只有函数跨 DLL 导出，数据符号不导**；`MAHO_API` 在 插件侧展开为空（插件自己的 `MAHO_<NAME>_API` 才是有效标签）。非 `MAHO_BUILD_SHARED`（静态链接） 时三者都为空，所以任何模块都可以无条件写它。

宏 MAHO_EXPORT

Windows 的导出标签（`__declspec(dllexport)`）。

宏 MAHO_IMPORT

Windows 的导入标签（`__declspec(dllimport)`）：把"消费方自己生成一份虚表/删除析构符" 变成编译错误，而不是留到运行时在 `delete` 里静默崩。

宏 MAHO_API

本模块的 API 标签：编译本模块时 = 导出。

Public/Core/Fatal.h

Fatal.h

致命 / 错误上报路径与断言宏：`MAHO_CHECK` / `MAHO_VERIFY` / `MAHO_ENSURE` 及它们的格式化版本。 三档语义（按"该不该继续"分，不是按严重程度分）： * `MAHO_CHECK` / `MAHO_CHECKF` —— **契约**被破坏就 `fatal`：这是一个 bug，继续跑只会把错误藏得更深。 * `MAHO_VERIFY` —— 永远生效（不受 `MAHO_DO_CHECK` 影响）：用于 `Shipping` 也要检查的不变量。 * `MAHO_ENSURE` / `MAHO_ENSURE_BREAK` —— **只报一次**、不中断：外部数据 / 环境导致的可疑情况。 `MAHO_CHECK` / `MAHO_CHECKF` / `MAHO_ENSURE*` 在关闭检查的构建（`Shipping`）里编译成 `((void)0)`： 所以它们**只能**放表达式（不能放有副作用的语句），参数在那种构建里不会被求值。 `MAHO_DO_CHECK` / `MAHO_DO_ENSURE` 由构建配置注入（见 AGENTS 的 Build Configuration）。

Public/Core/MetaData.h

MetaData.h

The engine's metadata store: every module files rows of `(Type, Key, Value)` here, and every module can look them up -- the engine's replacement for RTTI. The manager interprets NOTHING: `Type` and `Key` are strings the registering side chose, `Value` is bytes it encoded, and the store only answers "what did you file". A reader and a writer that agree on the encoding therefore share data across DLL boundaries without sharing a type -- which is how a declared TYPE gets an identity (`MAHO_DECLARE_TYPE`), a stage declares what it touches and a resource declares its ordering semantics.

Public/Core/Query.h

Query.h

Querying one object for another CAPABILITY it also implements, without RTTI. This is the mechanism that replaces `dynamic_cast` in the engine: a DECLARED type's identity is the address of the row its `MAHO_DECLARE_TYPE` filed in the store, so "is this thing also an X?" is a token compare plus one virtual call, and a type that declared nothing simply answers nullptr. A frame declares itself with `MAHO_QUERY_CASTER`; consumers ask through `QueryCast` or a `FQuery`/`FQueryResult` filter chain.

Public/Core/ThreadPool.h

ThreadPool.h

The engine's threading: one pool of workers (+ lanes), and the RESIDENT ROLE that lives on a lane of it. Two shapes of the same thread set, which is why they share a header: * `FThreadPool` -- N workers serving every SHARED lane. A lane is one owner's queue, so a barrier can drain exactly that owner's work instead of the whole process's. * `FThreadedServer` -- a PERSISTENT lane: a dedicated thread of the same pool serves it and nothing else. That is what a module owning an OS handle needs (a Win32 message queue belongs to the thread that created it -- see AGENTS "Thread Affinity"). The pool is the only place threads are created, named, or drained; a layer does not own a thread of its own any more.
